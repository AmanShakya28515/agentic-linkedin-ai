🤖 LinkedIn AI — Complete Architecture

Phase 1 → Phase 19 · Django + LangGraph + Groq + ChromaDB

① Phase Timeline — What Each Phase Added
Phase 1
Basic Pipeline
research → hook → write → review. Straight line. No human control.
Phase 2
HITL + Routing
Graph pauses for human. Approve or give feedback. Loops back to writer.
Phase 3
Skills Refactor
LLM calls extracted into reusable skill files. One file per job.
Phase 4
Orchestrator
One chat input. AI classifies: new topic / approve / feedback.
Phase 5
Groq Switch
OpenRouter → Groq. 14,400 req/day. 1 file change.
Phase 6
Streaming SSE
Tokens appear word by word in real time. Two content paths created.
Phase 7
Supervisor Pattern
Monolith → specialized sub-agents. Supervisor only sees interfaces.
Phase 8
Structured Output
Pydantic models. LLM returns guaranteed JSON. No text parsing.
Phase 9
Long-Term Memory
Preferences saved to JSON. Injected into every writing prompt.
Phase 10
Web Search Tools
Brave Search API. Real data, not hallucinations. ReAct agent loop.
Phase 11
RAG — Post Style
Approved posts stored in ChromaDB. Similar posts retrieved as style guide.
Phase 12
Prompt Enhancer
"messi" → rich writing brief with angle, tone, emotion, audience.
Phase 13
Planning Agent
Decides post type, angle, tone, hook style before writer starts.
Phase 14
Multi-Tool Research
3 tools: Brave, News, Reddit. LLM picks the right ones per topic.
Phase 15
Campaign Agent
Full 5-day content campaign. Different angle per day. One request.
Phase 16
Document Upload
Upload PDF/TXT → extract → chunk → store in ChromaDB.
Phase 17
Multi-Namespace RAG
6 separate collections. LLM router picks relevant ones. Org data > web.
Phase 18
Persona Writing
CEO / Developer / Sales / HR voices. Same topic, different post.
Phase 19
Brand Enforcer
Auto compliance check. Banned words caught. Rewritten before human sees it.

③ The Two Content Paths (Phase 6 Split)
🔵 New Topic Path — /message/stream/ (SSE)
1. User types a new topic
↓
2. Namespace router → selects relevant org collections (Ph 17)
↓
3. Org data found? → use it. Not found? → web search (Ph 17)
↓
4. hook_skill → generates 3 hook options
↓
5. writing_skill_stream → tokens sent to browser word by word (Ph 6)
↓
6. Full draft assembled from all tokens
↓
7. brand_enforcer checks draft (Ph 19)
↓
8. Violations? → writing_skill rewrites → corrected_draft sent to browser
↓
9. start_supervisor_flow_with_draft → saves to LangGraph MemorySaver
↓
10. "done" event + thread_id sent to browser → PAUSED ⏸
OR
🟣 Feedback/Approval Path — /message/
1. User types "looks good" or "make it shorter"
↓
2. orchestrator_skill classifies: approved / feedback (Ph 4)
↓
3. resume_supervisor_flow(thread_id, human_input)
↓
4. LangGraph resumes from checkpoint at human_review
↓
IF APPROVED:
5a. save_topic + store_post (Ph 9/11) → final_post returned
↓
IF FEEDBACK:
5b. writing_agent rewrites with persona + feedback (Ph 18)
↓
6b. brand_enforcer_node checks new draft (Ph 19)
↓
7b. human_review pauses again ⏸ → new draft sent to browser

⑥ What Goes Into the Writing Prompt (Phase 9 → 18)
PERSONA SECTION (Ph 18) — CEO / Developer / Sales / HR voice rules. Empty for "default".
ENHANCED TOPIC (Ph 12) — prompt_enhancer expands "messi" into a full writing brief with angle + tone + audience.
CONTENT PLAN (Ph 13) — post_type, angle, tone, hook_style from planning_agent.
RESEARCH — org data (Ph 17) OR web search summary (Ph 10/14).
HOOKS — 3 hook options generated by hook_skill.
FEEDBACK SECTION — reviewer feedback + human feedback (both included when revising).
MEMORY RULES (Ph 9) — "STRICT USER RULES: prefers short posts, no hashtags..."
ORG RAG CONTEXT (Ph 17) — specific facts from uploaded docs: prices, names, numbers.
STYLE EXAMPLES (Ph 11) — similar viral posts + your past approved posts from ChromaDB.
STRICT FORMAT RULES — max 250 words, punchy hooks, no passive voice, CTA ending.
